# Study Behaviour Monitor — USB POC

A small Android app runs Google ML Kit Face Detection on the phone. A local Streamlit dashboard receives numeric measurements over USB and estimates whether the student's head is facing the phone screen or turned away.

```text
Phone camera → ML Kit → numeric JSON → USB / adb logcat → Streamlit rules and dashboard
```

No FastAPI server, internet connection, account or API key is needed while using the POC. Initial dependency downloads require internet. Camera frames stay on the phone. The phone displays its preview; the laptop displays measurements, not video.

This estimates head direction, **not exact eye gaze, attention or learning**. Someone can face forward while moving their eyes elsewhere. It does not detect physical phones, emotions, sleep or homework progress. Use it with consent. There is no notebook position and no mandatory calibration.

## What is in the project?

| File or folder | Purpose |
| --- | --- |
| `android/` | Independent Kotlin app: CameraX preview, bundled ML Kit detector, numeric telemetry |
| `app.py` | Simple Test mode plus Tune / calibrate mode, saved settings and live results |
| `study_monitor/telemetry.py` | Validates the JSON sent by Android |
| `study_monitor/usb.py` | Reads only our telemetry tag through ADB and rejects old/invalid data |
| `study_monitor/rules.py` | Phone-facing thresholds, optional reference capture and time-based decisions |
| `tests/` | Checks that need neither a phone nor Android Studio |

The existing `base.apk` is not used or modified. Install the app built from this project.

## 1. Build and install the Android app

Install Android Studio, then open the **`android`** directory as a project. Use JDK 17 for Gradle, Android SDK Platform 35 and Build Tools 34.0.0. Let Gradle sync and build the app. The project includes a Gradle wrapper; no separate Gradle install is needed.

Use Android Studio's Run button with a connected phone, or build from PowerShell:

```powershell
cd C:\Users\aryan\Desktop\Personalized_Education\Study_Behaviour_Monitor_POC\android
.\gradlew.bat assembleDebug
```

The APK is `android\app\build\outputs\apk\debug\app-debug.apk`. It targets Android 6.0 / API 23 and above. Performance and face detection still need checking on your actual phone.

Alternatively, after a successful GitHub Actions build, open the repository's **Actions** tab, select the latest successful **Check rules and build Android APK** run and download the **study-monitor-debug-apk** artifact. Unzip it to get the APK. This avoids installing a full Android build environment on the laptop; you still need Platform Tools for USB. The artifact is retained for 14 days and can be regenerated by running the workflow again.

If Gradle reports Java 8, select JDK 17 in Android Studio's Gradle settings, or set your terminal's `JAVA_HOME` to an installed JDK 17. If the SDK cannot be found, configure its location in Android Studio. Keep generated `local.properties` out of Git.

For this laptop, C: has little free space. Prefer D: for Android SDK and build caches. Do not download a full emulator; this POC uses a physical phone.

## 2. Connect USB

1. On the phone, enable Developer options (usually by tapping Build number seven times).
2. Enable **USB debugging**.
3. Connect a data-capable USB cable, unlock the phone and approve the computer's debugging prompt.
4. Install Android SDK Platform Tools, either through Android Studio or [Google's standalone download](https://developer.android.com/tools/releases/platform-tools).

Check the connection using your actual Platform Tools location:

```powershell
& 'D:\Android\platform-tools\adb.exe' devices -l
& 'D:\Android\platform-tools\adb.exe' install -r '.\android\app\build\outputs\apk\debug\app-debug.apk'
```

The device should say `device`, not `unauthorized` or `offline`. Some phones require a manufacturer USB driver. Only authorize computers you trust; revoke USB debugging authorization afterwards if appropriate.

## 3. Run Streamlit

From the project root, using the existing `langchain` environment:

```powershell
cd C:\Users\aryan\Desktop\Personalized_Education\Study_Behaviour_Monitor_POC
micromamba run -n langchain python -m pip install -r requirements.txt
micromamba run -n langchain python -m streamlit run app.py --server.address 127.0.0.1
```

The only Python dependency is Streamlit 1.50.0. The USB reader, validation, rules and tests use Python's standard library. Python 3.10+ is required.

Open `http://localhost:8501`. Enter the full path to `adb.exe` if it is not on PATH. Alternatively, extract Platform Tools into this project's ignored `tools` folder so `tools/platform-tools/adb.exe` exists; the app discovers it automatically. Click **Refresh devices**, choose the phone and click **Connect dashboard**. Open **Study Monitor USB** on the phone, allow camera access and press **Start**. No port forwarding is required.

The Android app writes only the dedicated `StudyMonitor` numeric log tag. The reader does not clear your phone logs or stop the shared ADB server. No root access is required.

## 4. Use Test mode

1. Keep the phone's front camera near eye level, with the face clearly visible.
2. Leave the phone app open and press **Start**. Approve camera access if asked.
3. In Streamlit, **Refresh devices**, choose the phone and press **Connect**.
4. Leave **Mode → Test** selected. No calibration is required.
5. Face the phone, then turn sideways or look up/down. Brief movements wait for the configured delay.

The large central result is **FACING THE SCREEN**, **LOOKING AWAY**, or **CANNOT ASSESS YET**. Missing/multiple faces, unavailable camera data and stale measurements are Unknown, not automatically looking away. During a short movement the previous result can remain until its delay expires; a progress bar shows the pending change. Old head-angle values are not presented as live measurements.

## 5. Optional: Tune / calibrate mode

Choose **Tune / calibrate**. Controls are on the **left** and the large live result and measurements are alongside them on the **right**. Adjust angle tolerances, delays and smoothing while watching the result. Click **Save settings and test** when satisfied. This returns to the simple Test screen using the saved values. Merely switching back to Test discards unsaved edits.

The optional **Capture front-facing position** control records a five-second median while looking directly at the phone. It is only needed if default front-facing angles do not fit the camera placement. It retries on movement greater than 10 degrees, missing faces or measurement gaps. **Use default front-facing angles** removes this personal reference. There is no second position to capture.

Defaults:

| Setting | Initial value |
| --- | --- |
| Front-facing reference | yaw 0°, pitch 0° |
| Horizontal tolerance | ±20° |
| Vertical tolerance | ±15° |
| Looking-away delay | 5 seconds |
| Facing-screen delay | 2 seconds |
| Smoothing alpha | 0.3 |
| Missing/stale measurement deadline | 1 second |

The defaults are starting hypotheses, not accuracy guarantees. The only accepted head position is front-facing, around the default or optionally captured reference.

**Disconnect** stops the laptop reader only. Use **Stop on the phone** to release its camera. Leaving the phone app stops capture; returning requires pressing Start again. The app does not monitor you in the background while using another Android app.

Saved settings last for the current Streamlit browser session. Use the visible **Download tuned settings (.json)** button in Tune, or **Download active settings (.json)** in Test, to keep a version 2 file. The Tune download includes the current edits, even before Save. Downloads and Save are disabled while a reference capture is incomplete.

To use someone else's tuned settings, load their file in the sidebar under **Import settings → Load a tuned settings file (.json)**. Validated settings become active in the current dashboard and are saved for Test mode. You do not need to edit code or reinstall the phone app. This does **not** overwrite repository defaults or retrain ML Kit. Older two-position exports and malformed settings are rejected. Captured reference angles depend on the person and camera placement; generic thresholds still need checking on each setup.

Manual labels and measurement exports are hidden in an optional Tune-mode expander. The dashboard retains at most 1,500 recent samples in memory and does not automatically write video or exports to disk. Numeric face measurements and captured references are still personal data. Android temporarily buffers numeric telemetry in its system logs.

## Can another user connect their phone through Streamlit Cloud?

**Not with this USB implementation.** Python and ADB execute on the machine hosting Streamlit. On Streamlit Cloud that is a remote server, not the laptop with the user's USB cable. Installing ADB on that server does not give it access to the user's phone.

Another user can install the APK, run this dashboard **locally on their own laptop**, connect their phone by USB and use Test mode with defaults or an imported settings file. Remote phone-to-dashboard delivery needs the additional receiver described under Next steps.

Connecting a new phone does **not** automatically install the APK, enable USB debugging or approve camera access. Install the POC APK once per phone and approve the required prompts yourself.

## Share with another person without Git

They do not need to clone with Git. On the GitHub repository, choose **Code → Download ZIP** and extract it. Download the built APK from the Actions artifact as described above, and install it on the phone. Install Python (tested with 3.12) and Google Platform Tools on the laptop, then run from the extracted project directory:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m streamlit run app.py --server.address 127.0.0.1
```

Extract Platform Tools into `tools/platform-tools`, or enter its `adb.exe` path in **Advanced USB setup**. Enable USB debugging, approve the laptop, open the phone app and press Start. Open the local dashboard, refresh devices and connect. Optional: import the settings file shared by the person who tuned them.

## Troubleshooting

- **ADB not found:** enter the full `adb.exe` path, not its parent directory.
- **No phone:** check the data cable, USB debugging and Windows USB driver.
- **Unauthorized:** unlock the phone and accept its debugging prompt; refresh devices.
- **Connected, no data:** install this project's app and press Start. The old APK does not emit this contract.
- **Unknown:** inspect the reason. Face missing, multiple faces, a small/out-of-frame face or old measurements are deliberately not classified. Calibration is not required.
- **Dashboard fell behind:** old readings are discarded and timers restart. Keep the local browser tab active while tuning.
- **After reconnect/restart:** reconnect the dashboard. If using a personal reference and the camera moved, use default front-facing angles or capture a new reference.
- **Using a different camera:** ML Kit angles refer to the input image, not the mirrored front-camera preview. Camera placement can require different tolerances or an optional reference.
- **APK update incompatible:** APKs built on different computers/runners can have different debug signing keys. Remove the previous POC app from the phone manually before installing the new debug build.

You can inspect just the app's live output yourself:

```powershell
& 'D:\Android\platform-tools\adb.exe' logcat -v raw 'StudyMonitor:I' '*:S'
```

## Next steps

For a mentor to use their phone with a remotely hosted dashboard, add a small FastAPI receiver for numeric measurements. The phone would send them over the internet instead of USB. Keep the same telemetry fields and rule engine. This remote mode is **not implemented**: hosted Streamlit cannot read a phone connected to someone else's laptop by USB.

Keeping USB with a cloud dashboard would instead require a small **local USB bridge** that reads the phone on the laptop and forwards measurements to a hosted receiver. A browser-side WebUSB/ADB component is another possible direction but needs substantial browser-specific work and is not a drop-in Streamlit feature. Neither approach is implemented in this POC. Installing ADB on Streamlit Cloud alone does not solve the connection problem.
